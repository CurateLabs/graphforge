# Disposable Fly S20 certification

This controller runs one real S20 lifecycle in a pinned image. It does not use
synthetic S18/S19 qualification rungs, infer machine size from edge count, or
authorize S26. The image must perform generate, streamed ingest, source reopen
and count, unrooted one- and two-hop queries, portable export and verification,
clean import, and imported reopen/count/query. The retrieved artifact is the
only evidence.

Dry-run is the default. The plan is fixed at two performance CPUs and 4096 MiB;
the volume is explicit and cannot exceed Fly's 500 GB limit. Persistent graph
size is expected to be disk-bound. Phase RSS must remain bounded; growth is an
architecture failure signal, not justification for silently choosing more RAM.

```bash
python3 scripts/fly-g500-s20.py \
  --expected-sha "$GIT_SHA" \
  --image "registry.example/graphforge@sha256:<64-hex>" \
  --region ord --org curatelabs \
  --app-name gf-s20-<unique> --machine-name gf-s20-<unique> \
  --volume-name gf_s20_<unique> --volume-size-gb 500 \
  --ledger ./fly-cost-ledger.json --evidence-out ./g500-s20-evidence.json \
  --diagnostic-out ./g500-s20-diagnostic.json
```

Execution additionally requires `--execute --confirm-disposable`. The durable
controller first pulls the digest-pinned image and authenticates its exact
repository digest, `org.opencontainers.image.revision` SHA, and supported
GraphForge runtime-schema label. It then selects exactly one official Fly
`performance-2x`/4GB row for the fixed region and the one published volume
rate. Missing, duplicate, ambiguous, or above-ceiling pricing fails before any
provider mutation. The durable ledger reserves that applicable price for four
hours plus ten cleanup minutes and five billed volume hours. It never refunds
failed attempts; every existing entry is validated and recomputed with decimal
cents, and aggregate reservations cannot exceed $10. The controller refuses an
existing app, creates no service, pins the digest and region, and verifies the
created volume's observed ID, region, and size plus the Machine's exact `/work`
mount before accepting the run.

Cleanup converges child-first on success and failure: each observed Machine,
volume, and app is destroyed and polled to confirmed absence with bounded
retries before its parent is touched. A survivor or provider error is surfaced,
not silently ignored. While the result file is absent, the controller retrieves
the allowlisted active phase and durable journal, polls the Machine terminal
state, and promptly records a closed `machine_oom` or `machine_exit` diagnostic.
Successful evidence is bound to `/work/s20-evidence.json`. Provider IDs,
credentials, and absolute paths are forbidden from the closed evidence schema.
