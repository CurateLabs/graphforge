# Disposable Fly S20 certification

This controller runs one real S20 lifecycle in a pinned image. It does not use
synthetic S18/S19 qualification rungs, infer machine size from edge count, or
authorize S26. The image must perform generate, streamed ingest, source reopen
and count, unrooted one- and two-hop queries, portable export and verification,
clean import, and imported reopen/count/query. The retrieved artifact is the
only evidence.

Dry-run is the default. The plan is fixed at two performance CPUs and 4096 MiB;
the volume is explicit and cannot exceed Fly's 500 GB limit. Persistent graph
size is expected to be disk-bound. Phase RSS must remain bounded; growth is an
architecture failure signal, not justification for silently choosing more RAM.

```bash
python3 scripts/fly-g500-s20.py \
  --expected-sha "$GIT_SHA" \
  --image "registry.example/graphforge@sha256:<64-hex>" \
  --region den --org curatelabs \
  --app-name gf-s20-<unique> --machine-name gf-s20-<unique> \
  --volume-name gf_s20_<unique> --volume-size-gb 500 \
  --reserved-cost-usd 10 --ledger ./fly-cost-ledger.json \
  --evidence-out ./g500-s20-evidence.json
```

Execution additionally requires `--execute --confirm-disposable`. The durable
ledger reserves spend before any resource is created and never refunds failed
attempts; aggregate reservations cannot exceed $10. The controller refuses an
existing app, creates no service, pins the digest and region, disables restart,
and destroys only the Machine, volume, and app IDs observed from this invocation.
Cleanup runs child-first on success and failure. Provider IDs, credentials, and
absolute paths are forbidden from the closed evidence schema.
