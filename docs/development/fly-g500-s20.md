# Disposable Fly S20 certification

This runbook builds and runs one real Graph500 S20 lifecycle in an immutable
image. The lifecycle is generate, streamed construction, source reopen and
recount, unrooted one- and two-hop ordered-`LIMIT` queries, portable-v2 export,
full verification, clean import, and imported reopen/recount/query. It uses the
ordinary public Rust facade and `GraphConstructionSession`; there is no
ladder-only engine or binding fallback.

The S20 plan is fixed at two performance CPUs, 4096 MiB, one private Machine,
and one explicitly sized Fly volume in a fixed region. Persistent graph size is
expected to be disk-bound. More RAM is not an admissible repair for resident
memory that continues to grow with edge count.

## Before spending

Work from a clean, exact candidate commit. Run the deterministic controller,
schema, evidence, and repository-policy checks before building an image:

```bash
git status --short
export GIT_SHA="$(git rev-parse HEAD)"
test "$(git status --porcelain)" = ""
make fly-g500-s20-check
make pre-push-fast
```

`make fly-g500-s20-check` does not contact Fly or create resources. Review all
intentional changes, then push the exact candidate commit so the SHA recorded
in the image is independently retrievable.

The operator needs Docker with `buildx`, `flyctl` authenticated to the intended
organization, and a container registry that Fly can pull. The example below
uses GHCR and requires GitHub `write:packages` permission. Use a dedicated image
name; do not overwrite a release image.

```bash
export GHCR_USER="$(gh api user --jq .login)"
export IMAGE_TAG="ghcr.io/curatelabs/graphforge-s20:${GIT_SHA}"
gh auth token | docker login ghcr.io --username "$GHCR_USER" --password-stdin

docker buildx build \
  --platform linux/amd64 \
  --provenance=false --sbom=false \
  --build-arg "GRAPHFORGE_GIT_SHA=$GIT_SHA" \
  --file containers/fly-g500-s20/Dockerfile \
  --tag "$IMAGE_TAG" --push .

# The controller deliberately supplies no registry credential to Fly.
gh api --method PATCH \
  /orgs/CurateLabs/packages/container/graphforge-s20 \
  -f visibility=public >/dev/null

docker pull "$IMAGE_TAG"
export IMAGE_REF="$(docker image inspect "$IMAGE_TAG" \
  --format '{{index .RepoDigests 0}}')"
case "$IMAGE_REF" in *@sha256:????????????????????????????????????????????????????????????????) ;; *) exit 2 ;; esac

export SOURCE_SNAPSHOT="$(python3 scripts/ci/fly-s20-source-attestation.py .)"
export PROVENANCE_FILE="$(mktemp -t graphforge-s20-provenance.XXXXXX)"
export IMAGE_CONTAINER="$(docker create "$IMAGE_REF")"
docker cp \
  "$IMAGE_CONTAINER:/usr/local/share/graphforge/build-provenance.json" \
  "$PROVENANCE_FILE"
docker rm "$IMAGE_CONTAINER" >/dev/null
jq -e --arg sha "$GIT_SHA" --arg snapshot "$SOURCE_SNAPSHOT" \
  '.schema == "graphforge-fly-s20-build-provenance/1" and
   .source_sha == $sha and .source_snapshot_sha256 == $snapshot' \
  "$PROVENANCE_FILE" >/dev/null
rm "$PROVENANCE_FILE"
```

The package must be public because the private Machine receives no registry
secret. The build contains the test binary, not graph data or credentials. It
compiles the S20 test binary; the Fly Machine never compiles source.
The image embeds the exact source SHA and a content snapshot. The controller
pulls the digest reference and independently checks its repository digest,
`org.opencontainers.image.revision`, runtime-contract label, and embedded source
snapshot before any Fly mutation.

Choose unique names and paths outside the repository so the clean-tree and
source-snapshot checks remain stable. Keep the cost ledger permanently: every
reservation counts against the authorized total, including failed attempts.

```bash
export RUN_TAG="$(date -u +%Y%m%d%H%M%S)"
export RUN_DIR="$(mktemp -d -t graphforge-s20.XXXXXX)"
export FLY_ORG="curatelabs"
export FLY_REGION="ord"
: "${GF_S20_LEDGER_PATH:?set one durable absolute ledger path reused by every attempt}"

python3 scripts/fly-g500-s20.py \
  --expected-sha "$GIT_SHA" \
  --image "$IMAGE_REF" \
  --region "$FLY_REGION" --org "$FLY_ORG" \
  --app-name "gf-s20-$RUN_TAG" \
  --machine-name "gf-s20-$RUN_TAG" \
  --volume-name "gf_s20_${RUN_TAG}" --volume-size-gb 500 \
  --ledger "$GF_S20_LEDGER_PATH" \
  --evidence-out "$RUN_DIR/g500-s20-evidence.json" \
  --diagnostic-out "$RUN_DIR/g500-s20-diagnostic.json"
```

That invocation is the mandatory dry-run. Inspect the printed plan, confirm
the SHA, digest, region, two CPUs, 4096 MiB, volume size, and reserved cost, and
retain it with the run record. A dry-run performs no provider mutation.

## Execute the S20 lifecycle

Only after the dry-run and authorization checks pass, execute the same pinned
plan with the two mutation confirmations:

```bash
python3 scripts/fly-g500-s20.py \
  --expected-sha "$GIT_SHA" \
  --image "$IMAGE_REF" \
  --region "$FLY_REGION" --org "$FLY_ORG" \
  --app-name "gf-s20-$RUN_TAG" \
  --machine-name "gf-s20-$RUN_TAG" \
  --volume-name "gf_s20_${RUN_TAG}" --volume-size-gb 500 \
  --ledger "$GF_S20_LEDGER_PATH" \
  --evidence-out "$RUN_DIR/g500-s20-evidence.json" \
  --diagnostic-out "$RUN_DIR/g500-s20-diagnostic.json" \
  --execute --confirm-disposable
```

The controller obtains the current official fixed-region price, validates the
durable reservation ledger, refuses an existing app, and then creates exactly
one app, volume, and private Machine. The Machine has no service, restart is
disabled, auto-destroy is enabled, the immutable image is pinned, and the
volume is mounted at `/work`. The four-hour lifecycle timeout and ten-minute
cleanup reservation are part of the cost calculation; aggregate reservations
may not exceed $10.

Do not separately stop, restart, resize, or delete resources while the
controller is active. It retrieves the last durable phase/query/ingest journal
when evidence is absent and polls terminal Machine state so an OOM or abrupt
exit is attributed to the last completed operation.

## Evidence interpretation

The only pass artifact is the retrieved, schema-valid
`g500-s20-evidence.json`. Console output, a surviving project, a green lower
test, or an exit code without this artifact is not an S20 pass. Revalidate a
retrieved artifact independently:

```bash
uv run --frozen --with jsonschema python \
  scripts/ci/validate-fly-g500-s20.py \
  "$RUN_DIR/g500-s20-evidence.json" \
  --expected-sha "$GIT_SHA" \
  --expected-image-digest "${IMAGE_REF##*@}" \
  --expected-region "$FLY_REGION"
```

Interpret `phase_memory` at these exact boundaries:

- `generate` owns bounded Graph500 generation and disk runs.
- `ingest` owns node publication, edge merge/chunks, resume, and the single
  final `seal_and_publish` publication.
- `source_reopen` separates open, node recount, and edge recount.
- `source_query_1hop` and `source_query_2hop` independently record expansion,
  bounded top-k/spill, release, and RSS for each source query.
- `export`, `verify`, and `import` cover the complete portable-v2 round trip.
- `imported_reopen` repeats the authoritative counts against the clean import.
- `imported_query_1hop` and `imported_query_2hop` independently repeat the
  query proofs against the clean import.
- `finalize` reconciles counts, storage, authority fingerprints, and the final
  sanitized artifact.

For memory, compare current RSS, process HWM, anonymous RSS, and file RSS—not
only the final HWM. `ingest_memory_windows` divides authenticated committed
edge-chunk progress into early, middle, and late thirds. Startup, node
publication, final sealing, and recovery replay are excluded from these bands.
The final committed chunk is included. `sampling_source` is
`authenticated_edge_chunk_commit`: the construction path takes one synchronous
RSS and progress sample immediately after every successful 8,192-row
`append_edges` receipt. This does not mean the 1,048,576-row outer merge buffer,
and it avoids weighting slow appends through repeated time polling. Each band
exposes its authenticated progress range, distinct committed-chunk count, and
sample count and must contain at least three distinct committed chunks and
three samples. Missing or undersampled bands fail the proof. The separate
phase-level memory peaks remain sampled every 250 ms.

`allowed_growth_bytes` must equal the measured construction
`peak_accounted_live_bytes` plus the fixed 67,108,864-byte sampler-noise
allowance. It is independent of Machine size and edge count.
`observed_growth_bytes` is the maximum of the positive early-to-middle,
middle-to-late, and cumulative early-to-late RSS differences; every negative
difference saturates at zero. The run passes the plateau rule only when that
observed maximum is no greater than the measured allowance. `headroom_bytes`
must equal the 4096 MiB envelope minus the largest observed window and must be
positive. A failed `plateau_pass`, even when the process finishes, is an
architectural failure. File-backed growth and volume I/O are assessed
separately from anonymous memory.

The ordered `durable_steps` proof must contain exactly:

1. `construction_published`
2. `construction_recovered`
3. `source_reopened`
4. `source_query_1hop_completed`
5. `source_query_2hop_completed`
6. `export_completed`
7. `verify_completed`
8. `import_completed`
9. `imported_reopened`
10. `imported_query_1hop_completed`
11. `imported_query_2hop_completed`

Each query record must show bounded frontier/top-k or spill state, zero retained
query reservation after completion, and its own memory observation. A journal
ending before a completion record identifies that exact operation as
incomplete; do not infer success from the next phase.

Construction evidence must reconcile attempts, self-loop rejects, duplicate
rejects, accepted/live rows, chunk and shard work, authentication reads,
write/sync work, bounded buffer peaks, resume/re-entry, and exactly one final
generation publication. `construction.edge_batch_commits` counts the successful
8,192-row edge receipts and must equal
`ingest_memory_windows.final_committed_chunks`. For S20,
`construction.input_batches` must equal `edge_batch_commits + 128`, where the
128 additional receipts are the `2^20 / 8192` node batches. The `publication`
proof derives `commits` by counting
non-idempotent publication receipts across the original seal and recovery
replay and requires that measured count to equal one. Recovery must succeed,
and the hashed published/recovered generation authority must match. The source
and imported counts and query fingerprints must match.
Storage evidence keeps logical bytes distinct from allocated bytes, classifies
every retained artifact, counts shared/CAS objects once physically, and
distinguishes retained allocation from transient lifecycle peak.

The checked-in artifact must not contain graph values, paths, credentials,
provider resource IDs, or raw project/generation UUIDs. It may contain only the
closed aggregate schema, hashed generation authority, counts, timings, memory,
and storage facts.

## Failure, recovery, and cleanup

Any missing/invalid evidence, typed diagnostic, timeout, OOM, nonzero Machine
exit, count/fingerprint mismatch, positive material RSS slope, insufficient
headroom, unclassified storage, or incomplete teardown is a failed attempt.
Preserve the sanitized diagnostic and last journal; never relabel a partial
lifecycle as a pass.

The controller always converges cleanup child-first: Machine, volume, then app.
It destroys only identities observed from resources created by that invocation
and polls authenticated absence before proceeding. A survivor or provider error
is surfaced. After the command returns, verify the controller reported no
cleanup error and confirm that the uniquely named app is absent:

```bash
test -f "$RUN_DIR/g500-s20-evidence.json" || \
  test -f "$RUN_DIR/g500-s20-diagnostic.json"
! flyctl apps list --json | jq -e --arg app "gf-s20-$RUN_TAG" \
  '.[] | select((.Name // .name) == $app)' >/dev/null
```

If a resource survives, do not make another reservation or run. Record the
controller error, inspect the exact unique app, and complete verified teardown
before retrying. Never reuse the old app, Machine, volume, run name, or ledger
entry. A GraphForge lifecycle failure is diagnosed from the durable artifact;
provider cleanup is not a mechanism for modifying or resuming its graph.

Graph construction recovery itself is proven through the same public session:
an interrupted session reopens its authenticated checkpoint, preserves the
prior `CURRENT`, resumes without duplicate live rows, and publishes once.
Recovery/re-entry evidence must be present in the closed pass artifact; absence
is not waived because the uninterrupted lifecycle completed.

## Environmental caveats

- Fly volume capacity and storage I/O are expected to be the likely constraint;
  the 4096 MiB Machine is intentionally a memory-bounded product proof.
- The volume filesystem, capacity, fixed region, Machine resources, and `/work`
  mount are observed after creation. A mismatch fails admission.
- The image is Linux/amd64 and immutable. Local host performance and Docker
  filesystem behavior are not certification measurements.
- Fly pricing and regional capacity can change. Missing, duplicate, redirected,
  ambiguous, or above-ceiling official pricing fails before provider mutation.
- A 500 GB Fly volume is an environment limit, not a universal GraphForge
  product limit.
- The run is private and exposes no public service. Evidence is sanitized
  before it leaves the Machine; graph/package data is never a checked-in
  artifact.

## What S20 does and does not close

A valid S20 artifact can satisfy the live S20 portions of #900 and #904. Commit
the sanitized evidence and measured caveats to the focused S20 close PR, run
the exact-head repository CI and CI Gate, request the one final CodeRabbit
review only after those checks are green, resolve current findings, squash
merge, and verify the intended issue closure and branch deletion.

Do not close #951 or #901 from S20 alone. #951 separately requires attributable
S20 **and S22** observations plus a conservative adjacent-rung S26 storage
projection. S22 requires its own explicit authorization, measured S20 RSS and
disk headroom, and budget; this controller neither authorizes nor attempts it.
S24, S25, and S26 are outside this runbook. The billion-edge certification
issue #745 also remains open.
