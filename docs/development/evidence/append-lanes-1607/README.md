# Append preparation lanes: #1607 no-go

## Decision

Do not adopt the admission-lane append preparation candidate. It misses both predeclared performance gates after the #1606 routing disposition: at S18/8 the median append CPU/wall ratio is 0.926 (required >= 2.0); complete-ingest median wall improvement is 2.8% at S18 and 0.8% at S20 (each required >= 10%). No production change is retained. The candidate source diff is preserved as `candidate/experimental.patch.gz` for the measurements' provenance.

The largest candidate preparation region was 1.17 s wall / 1.43 s CPU at S18 and 4.62 s wall / 5.65 s CPU at S20. Even eliminating that entire region gives an optimistic whole-ingest ceiling of only 5.6% at S18 and 5.4% at S20, before accounting for any extra coordination cost. The ordered durable region remained 2.77 s wall / 2.24 s CPU at S18 and 11.15 s wall / 9.21 s CPU at S20. Preparation was not the dominant remaining opportunity, and the candidate's CPU/wall ratio stayed below one despite up to eight admitted cores. The measured bottleneck remains the ordered durable append path, with most append wall time in the combined artifact/control phase. Splitting that phase further or changing its durability protocol is outside this bounded issue.

This is the acceptance-criteria no-code disposition for #1607. It adds no ADR and leaves the integrated storage behavior unchanged.

## Method

The integrated baseline is commit `b9fc0432f2405ceae02aac96de9c35698f4e6a2e`, after #1606 closed with a no-go and without a production routing change. Baseline and candidate binaries were separately built in release mode and frozen by SHA-256 in `candidate/host-state.txt`. The candidate was built from that baseline plus the source patch in `candidate/experimental.patch.gz`.

The run used the #1448 S18/S20 inputs whose file hashes are recorded in `candidate/host-state.txt`. Six alternating complete-ingest runs were taken at each scale (three baseline/candidate pairs); the candidate S18 core curve used 1/2/4/8/16 CPUs, with three runs at 1 and 8 as prescribed. `candidate/driver.log` records every run start/end and post-run quiet check. All 21 ingests returned zero, all post-run checks were quiet, each run stayed within the 4,000 MiB cap, and the post-import node/edge count and full-scan queries succeeded. `candidate/results.txt` is generated by the checked-in summarizer; it validates the full run census and identical query-answer digests across all six A/B runs at each scale before reporting medians.

To reproduce the validation and summary on the recorded run bundle:

```bash
PYTHONPYCACHEPREFIX=/tmp/gf1607-pycache \
  python3 docs/development/evidence/append-lanes-1607/summarize.py \
  docs/development/evidence/append-lanes-1607/candidate
```

The candidate binary and original S18/S20 input data are environment artifacts, not committed. Their recorded digests make this evidence bundle auditable against the preserved local artifacts. `measure.sh` records the quiet-host A/B and core-curve procedure; it accepts frozen baseline and candidate binary paths plus the input directory.

## Results

| Measure | Baseline median | Candidate median | Change | Gate |
| --- | ---: | ---: | ---: | ---: |
| S18 complete ingest wall | 21.46 s | 20.87 s | 2.8% faster | >= 10% |
| S20 complete ingest wall | 86.49 s | 85.84 s | 0.8% faster | >= 10% |
| S18/8 append CPU/wall | — | 0.926 | — | >= 2.0 |

Candidate S18/8 append CPU/wall samples were 0.926, 0.844, and 0.943. At S18, baseline append was about 4.08–4.27 s wall and candidate append about 4.00–4.01 s; the candidate's preparation costs roughly matched the baseline's digest, fixed-run and Arrow preparation. At S20, baseline append was about 16.61–16.79 s and candidate append about 16.02–16.04 s. The full per-run timing, CPU, memory, pressure, region split, core curve, and query digests are in `candidate/results.txt`; raw receipts and query outputs are retained under `candidate/runs/`.

## Files

- `measure.sh`: reproducible run sequence and quiet-host admission checks.
- `summarize.py`: run census, resource-cap, and query-digest validation plus report generation.
- `candidate/host-state.txt`, `candidate/run-metadata.txt`: host, input, binary, baseline, and toolchain identity.
- `candidate/driver.log`, `candidate/results.txt`: run acceptance log and summarized evidence.
- `candidate/runs/`: raw BenchExec results, ingest logs, receipts, and reopened query answers.
- `candidate/experimental.patch.gz`: exact candidate source diff; none of it is retained in production.
