## GraphForge v0.6.0 candidate preview

GraphForge is an embedded, openCypher-compatible graph and analytics engine.
It runs inside your Python or Node process, or through the `gf` command, with
no database server. It is pre-v1.

### Who it is for

The core audience is a nontechnical analyst assisted by an agent. v0.6.0
initially serves technical analysts and integrators more completely: people
working in Python, Node, a notebook, or through a coding agent who want to
build or load a graph, ask relationship questions, and keep or share what they
learn. Implementation and automated examples do not establish human usability. See
[Who GraphForge is for](../guide/audience-and-fit.md) for the two jobs it
completes today and when an embedded engine does not fit.

### What is new

The current source provides local graph construction/querying, analyst verbs,
durable save/reopen, verified portable transfer, research Branches/Versions,
git-style CLI collaboration and installed agent guidance. Rust owns the
behavior; Python and Node expose thin bindings. See the
[research guide](../guide/research-journey.md) for optional history and collaboration.

These source capabilities are distinct from qualification of installed artifacts.
The [published rc.6 consumer results](https://github.com/CurateLabs/graphforge/issues/1209#issuecomment-6460385114)
establish local useful graph/reopen, retention and skills behavior on Linux
x86-64/ext4, not the production lifecycle or editor experience. Later source
with the same version string is not the registry artifact.

### Measured scale

On one host (OVHC-AGENCY, Ryzen 7 3800X, 125 GiB, ext4), at merged commit
`114b1964`, a Graph500-compliant generated project of **1,073,741,824 live
edges** completed generate, ingest, reopen, recount, query, export, verify,
clean import, and reopen proof with matching content digests, in 3,769 s with
31,040 MiB peak ingest memory and 216.3 GB retained storage.

- This is one run on one host and describes that workload. It is not a
  capacity promise and not a Graph500 performance claim.
- Complete-ingest throughput measured **184,749 edges/s** at 67,108,864 edges.
  The 1,000,000 edges/s target is not met; it is deferred and tracked in
  [#1387](https://github.com/CurateLabs/graphforge/issues/1387). No 1M edges/s
  claim is made.

Full table with workload, configuration, command, limits, and reproducibility
links: [Scale and workload limits](../reference/scale-limits.md#claims-and-their-evidence).

### Benchmark observations (unaudited)

A single frozen engineering campaign at source `15b354ce` ran the four GDC
suites. Graphalytics passed all four pinned rungs (63/63 measured results
checked and matched). SNB Interactive SF1 failed with 60 of 600 calls refused
for resource limits and 540 checked matches. FinBench and SNB BI hit the 4 GiB
phase cap with partial coverage. These are unaudited observations, not LDBC
Benchmark Results, and carry no sub-second or other performance claim. Results:
[#952](https://github.com/CurateLabs/graphforge/issues/952#issuecomment-6264547283).

### Install

For this candidate, use Python 3.10+ or Node.js 20+ and pin the package version:

```bash
python -m pip install "graphforge==0.6.0rc6"
npm install @curatelabs/graphforge@0.6.0-rc.6 apache-arrow@21.2.0
npx --yes @curatelabs/graphforge-cli@0.6.0-rc.6 --version
```

The npm CLI uses the bundled native engine but cannot initiate human device
approval. For that step, install the standalone Rust CLI with a Rust toolchain
and build prerequisites from [Installation](../guide/installation.md#build-from-source).
Select it by absolute path so another `gf` on `PATH` cannot take its place:

```bash
GF_NATIVE_CLI_ROOT="$PWD/graphforge-native-cli"
cargo install --locked --root "$GF_NATIVE_CLI_ROOT" --version 0.6.0-rc.6 graphforge-cli
"$GF_NATIVE_CLI_ROOT/bin/gf" --version
```

These shell commands use POSIX syntax. On Windows, use an absolute installation
root and its `bin/gf.exe`; the
[native approval instructions](../guide/portable-projects.md#continue-publish-back-discover-and-clone-again)
give the PowerShell commands. Native approval requires terminal stdin and stderr.
The crates.io route has the DataFusion limitations listed below. Use matching
Core, bindings, CLI and skills; neither route selects a final release candidate.
Full platform, environment and storage prerequisites: [Installation](../guide/installation.md).

### Hub journey (blocked pending qualification)

The coordinated journey is [browse the production Hub](https://graphforge.sh/hub)
→ exact CLI install → clone → durable reopen/query → continue locally →
`gf publish` → discover/clone the new Version. The
[launch guide](../guide/portable-projects.md#public-hub-launch-path) gives both
accepted clone forms, matching-runtime guidance and the agent path from
[#2127](https://github.com/CurateLabs/graphforge/issues/2127).

The intended [opendata/openalex](https://graphforge.sh/opendata/openalex) fixture
is GraphForge-generated synthetic content under CC0-1.0, with no real OpenAlex
records or official OpenAlex/OurResearch affiliation. Its production discovery
is currently unavailable. No production counts, useful query result, research
Version or producing Core identity has been qualified; the source fixture is
not production proof.

Publishing requires an existing owner account/repository, write permission and
the exact `publish:OWNER/REPOSITORY` scope, approved through the Hub's device
flow using the [standalone native CLI](../guide/portable-projects.md#continue-publish-back-discover-and-clone-again).
The npm launcher requires an already-provisioned explicit token. An unattended
agent needs a pre-provisioned scoped credential through the
[documented agent path](../guide/work-with-an-agent.md#provision-scoped-credentials-for-an-agent-or-ci).
Capability discovery alone is not publish-back proof.

As of the [2026-10-28 production checkpoint](https://github.com/CurateLabs/graphforge/issues/1209#issuecomment-6466493328),
the required fixture page and discovery refs return 404. The advertised legacy
fixture's manifest lacks the required producing Core version, and rc.6 refuses
it. Publish capability discovery responds, but no authorized device approval or
publish-back/discovery/clone result is established. No production graph counts
or paired deployed web/backend/Worker revisions are qualified. The existing
[local graph](../guide/quickstart.md) and
[portable export/verify/import](../guide/portable-projects.md#copy-the-graph-you-just-saved)
paths provide an alternative while Hub owners complete production adoption.

The required launch scope includes public browse/clone and the publish subset.
Full hosted catalog/publishing interfaces, private-repository/browser-login
qualification and later seed collections are separate. A failure of the
required production path delays the coordinated launch.

### Known issues and limits

- **Pre-v1.** No backward-compatibility, legacy-API, or migration guarantee.
  Only supported current-format projects open; others return
  `GF_UNSUPPORTED_PROJECT_FORMAT`. Data from a different Core version is not
  promised to read correctly. GraphForge warns when opening, importing, or
  cloning such data, naming both versions and how to get a matching runtime
  ([details](../guide/portable-projects.md#data-from-another-core-version)).
- **Durable storage** needs ext4, xfs, or btrfs on Linux (APFS on macOS, NTFS on
  Windows). Other filesystems fail with `GF_UNSUPPORTED_FILESYSTEM`. In-memory
  projects run the full engine.
- **Crates.io builds** (`cargo install graphforge-cli`) compile against stock
  DataFusion 54.1 and lack two fixes carried by the Python wheel and Node
  packages: a spill-pool hang
  ([apache/datafusion#24883](https://github.com/apache/datafusion/issues/24883))
  and a join-planning error ([#2084](https://github.com/CurateLabs/graphforge/issues/2084)).
- **Published Linux arm64 npm addon:** Hub HTTPS can fail with a certificate
  `BadSignature` error. [#2262](https://github.com/CurateLabs/graphforge/pull/2262)
  repairs C compilation and adds native arm64 HTTPS execution in later source;
  it does not change the immutable published rc.6 artifact. That package must
  not be described as containing the repair.
- **Ingest rate:** S22 measured 184,749 edges/s, below the 1,000,000 edges/s
  target. The cited eight-core S18 curve measured 1.39× one-core throughput and
  1.19 effective cores; strong multicore ingest scaling is not established.
- **GDC suites:** failed and incomplete as above.
  [#1982's closed maintainer disposition](https://github.com/CurateLabs/graphforge/issues/1982)
  transfers unresolved resource, coverage and reference outcomes to
  [#2178](https://github.com/CurateLabs/graphforge/issues/2178). Closure did not
  establish passing suites or resolve those outcomes.
- **Entry experiences:** production Hub/publish-back, packaged editor execution,
  hosted Kaggle/Colab and two independent human timing/comprehension reviews
  remain unqualified in [#1209](https://github.com/CurateLabs/graphforge/issues/1209#issuecomment-6460385114).
