# GraphForge v0.7.0 release notes (draft)

**Status: draft for the v0.7.0 development cycle. It is not approved, and
v0.7.0 is not published.** Final release notes go on the immutable
[GitHub Release](https://github.com/CurateLabs/graphforge/releases).
[#2042](https://github.com/CurateLabs/graphforge/issues/2042) owns the engine
migration below, and
[#2358](https://github.com/CurateLabs/graphforge/issues/2358) owns this record of

## Engine upgrade

v0.7.0 runs on stock, released Apache DataFusion and Arrow. Under the M16 rule,
an exposed Arrow or DataFusion major type change requires a new minor release,
even when the answers are identical.

| Dependency | v0.6.x | v0.7.0 |
| --- | --- | --- |
| DataFusion | 54.1 with two GraphForge forks (`datafusion-physical-plan`, `datafusion-optimizer`) | stock 56.0.0 from crates.io |
| Arrow / Parquet | 58.4.0, with a vendored `arrow-row` | 60.2.0, stock |
| object_store | 0.13.2 | 0.14.2 |
| PyO3 (Python binding) | 0.28.3 | 0.29.3, required by Arrow 60's `pyarrow` bridge |
| libzstd (Parquet and Arrow IPC) | 1.5.7 (zstd 0.14.2) | 1.6.0 (zstd 0.14.5) |
| lz4_flex (Parquet and Arrow IPC) | 0.13.1 | 0.14.2 |

- **The vendored crates are removed.** The `vendor/datafusion-physical-plan`,
  `vendor/datafusion-optimizer` and `vendor/arrow-row` directories and their
  `[patch]` entries are gone, including the `benchmarks/` workspace's overrides.
  The two fixes the forks carried ship upstream. The spilling-exchange deadlock
  fix ([apache/datafusion#24891](https://github.com/apache/datafusion/pull/24891))
  is in 56.0.0, and the optimizer fix
  ([apache/datafusion#22903](https://github.com/apache/datafusion/pull/22903))
  has been upstream since 55.0.0. Their GraphForge regression tests stay.
- **crates.io builds now run the same engine as the wheels and npm packages.**
  The v0.6.0 known issue, where `cargo install graphforge-cli` compiled against
  stock DataFusion without the fork's fixes, no longer applies.
- **Spill files are validated before they are decoded.** DataFusion 56 reads
  its own spill files with Arrow validation switched off. GraphForge now
  creates query spill files through DataFusion's public `TempFileFactory` seam.
  It checks every IPC frame's buffer layout and decodes the frame with Arrow's
  validating decoder before DataFusion sees it. A corrupt spill file fails the
  query with a `corrupt query spill file` error. It never panics or yields
  invalid arrays, and no allocation is sized from an unvalidated length.
  Spill files stay under the configured temporary directory and its size cap.
- **Answers, typed errors and documented resource bounds are unchanged.**
  Where Arrow 60 or libzstd 1.6 changed what a bound measures, the bound was
  re-derived for the new layout and was not loosened. Over-budget joins still
  finish on DataFusion 56's sort-merge path.

## Toolchain

- **Rust:** DataFusion 56 requires Rust 1.95.0 or later. GraphForge builds and
  tests with the pinned toolchain in `rust-toolchain.toml`, Rust 1.96.0, which
  did not change. The product crates declare no separate `rust-version`.
- **Python:** the wheel is still one `abi3` build for CPython 3.10+. Only the
  native PyO3 layer changed, and the Python API did not.
- **Node:** the addon still exchanges Arrow IPC with `apache-arrow` `^21.2.0`.

## On-disk format break: re-import v0.6.x projects

Arrow 60 writes different Parquet and IPC bytes than Arrow 58 for the same
logical data. Every artifact GraphForge writes through Arrow therefore has
different bytes and different content digests in v0.7.0. This covers topology
and CSR shards, property fragments, runtime catalogs, portable bundles and Hub
packages.

**There is no backward compatibility (maintainer decision, 2026-11-25).**

- v0.7.0 does not open projects that v0.6.x wrote, and v0.6.x does not open
  projects that v0.7.0 wrote. GraphForge provides no compatibility shim,
  dual-format reader, migration command or in-place upgrade.
- To keep v0.6.x data, export the source data with v0.6.x, then rebuild the
  project with v0.7.0's construction or import surface. Portable packages from
  another Core version are not promised to import correctly, and GraphForge
  warns when it opens, imports or clones one.
- Within v0.7.0, publication is deterministic as before
  ([ADR 0038](../adr/0038-determinism-at-the-publication-boundary.md)):
  identical logical input publishes identical bytes. The break is between
  versions only.
- The synthetic `opendata/openalex` Hub fixture was regenerated from the
  v0.7.0 writer, so its package, summary, manifest and refs digests changed.
  The previously published package bytes stay immutable, and Hub owns
  repinning its live content.

See [project format compatibility](../book/architecture/project-format-compatibility.md)
for the pre-v1 rule this applies.
